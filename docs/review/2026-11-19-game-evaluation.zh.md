# 《烬塔 · Spire of Ashes》游戏评估与改进方案

> **存档说明（2026-11-19 补交）**：这是对 AI Studio 初版（提交 `16dcb7d`）的第一次评估快照，原先只存在会话的临时文件夹里，没进仓库。报告里的 P0、P1 和 P2 余烬切片已在 PR #1–#5 完成，**问题清单不代表当前状态**；当前待办见 [skill-audit-2026-11-19.md](skill-audit-2026-11-19.md) 和 PR 记录。附录提到的 `balance_sim.ts` 已演进为 `scripts/balance_sim.ts`（`npm run sim`），`balance_sim_results.txt` 存为同目录的 [2026-11-19-balance-baseline.txt](2026-11-19-balance-baseline.txt)。

- **评估对象**：`animenzzz128/-Spire-of-Ashes`，提交 `16dcb7d`（2026-11-18）
- **评估方法**：
  1. **读代码**：通读游戏逻辑（engine、cards、enemies、map、events、relics，约 3.8k 行）和主要 UI 组件。
  2. **试玩**：在浏览器里用赤铁卫士打到第 10 层，再改存档跳到第 15 层看 Boss 战。测了 1440×900、1920×1080 和手机三种尺寸，也切到英文看了一遍。
  3. **模拟**：用游戏自己的引擎写了一个无界面模拟器，让规则 bot 每个职业跑 2000 局，另外跑了进阶 2 和几组对照。

---

## 一、总评

一句话：**这是一个表现层完成度很高的《杀戮尖塔》第一幕复刻原型。战斗反馈做得好，但难度曲线有断崖，内容太少，也还没有属于自己的东西。**

| 维度 | 评分 | 说明 |
|---|---|---|
| 战斗信息透明度 | 8/10 | 有意图数值、卡面实时伤害预览（易伤变绿、虚弱变红）、"敌方总攻 / 预计扣血"和 LETHAL 提示 |
| 美术与氛围 | 6/10 | 标题、立绘、场景和 Boss 图质量高，但 52 张牌只有 6 张插图 |
| 难度曲线与平衡 | 3.5/10 | 1–4 层几乎零风险，第 5 层断崖；两个职业胜率差约 5 倍 |
| 内容量与构筑深度 | 3.5/10 | 每职业约 20 张可得卡，12 件遗物，4 个事件，1 个 Boss |
| 原创性 | 2/10 | 卡牌、遗物、敌人和数值大面积沿用《杀戮尖塔》 |
| UI/UX | 5/10 | 手牌换行到首屏以外；遗物一多会挤掉"结束回合"；手机上没法玩 |
| 工程质量 | 6/10 | 引擎是纯函数、可测试、自带校验脚本；但效果系统写死、没有随机种子、干净环境下装不上依赖 |

**综合约 5/10。** 作为原型很扎实。要成为能放进作品集、能让别人长期玩的游戏，最需要的是**原创化**和**难度曲线**，而不是更多特效。

## 二、做得好的地方（应保留）

- **战斗可读性强。** 意图有图标和数值，卡面伤害会实时预览。只有一个敌人时自动选目标。1–9 快捷键出牌、E 结束回合，操作流畅。
- **引擎是纯函数**（`RunState → RunState`）。这次的模拟器直接调用它，没改一行源码。这是后面做平衡的基础。
- **能正常构建和校验。** `scripts/verify_game.ts` 的 6 组校验全部通过，`tsc` 没有报错，生产构建 0.4 秒。
- **细节用心。** 营火升级有前后对比，商店在药水栏满时会提示，有自动存档和继续游戏，还有局内伤害统计。
- **美术风格统一。** 标题页、立绘、三套战斗场景和 Boss 美术都是暗色金边风格，成立。

## 三、模拟数据：难度曲线与职业平衡

**bot 的策略**：先算来袭伤害补格挡，再把能量打在血最少的敌人身上，能力牌优先出。它不会对狂怒地精少出技能，也不会优先集火狂信徒，所以比熟练玩家弱。**绝对胜率只能当下限看，有意义的是不同遭遇、不同职业之间的差距。** 换成"少格挡、多进攻"的策略，结论不变（赤铁卫士 2.1%，暗影织者 13.7%）。

| 指标（进阶 0，各 2000 局） | 赤铁卫士 | 暗影织者 |
|---|---|---|
| 通关率 | **3.0%** | **16.3%** |
| 进阶 2 通关率 | 0.8% | 7.6% |
| 到达 Boss 的比例 | 25.4% | 50.1% |
| 到达 Boss 后的胜率 | 11.8% | 32.4% |
| 死在 1–4 层 | 0.4% | 0.1% |
| 死在 5–7 层 | **49.6%** | 30.7% |

下表是每场战斗的平均掉血和 bot 战败率（斜线前为赤铁卫士，后为暗影织者）：

| 遭遇 | 平均掉血 | bot 战败率 |
|---|---|---|
| 1–4 层单体怪 | 4–20 / 1–11 | ≈0% |
| 狂信徒 + 颚虫 | 42.7 / 26.3 | 57% / 33% |
| 骸骨护卫 + 掠夺者 | 38.1 / 20.8 | 33% / 13% |
| 狂怒地精贵族（精英） | 43.9 / 31.0 | 53% / 38% |
| 沉睡石像鬼（精英） | 35.5 / 15.2 | 27% / 13% |
| 古代哨兵 ×2（精英） | 10.3 / 3.1 | 2.7% / 1.2% |
| 黑曜守望者（Boss） | 58.3 / 44.9 | 88% / 68% |

**结论：**

1. **第 5 层是断崖。** `spawnEncounter` 在 1–4 层只刷单体怪，第 5 层起直接切到双怪池。5–14 层用的是同一个池，不随层数加强。
   - 结果是前 4 层没有学习压力，到了 5–7 层，有一半的赤铁卫士直接死掉。
   - 手动试玩也一样：打完 4 场还剩 75/80 HP。到第 10 层时我已经有 4 点能量和 2 张炽焰战意，用同样的简单出牌策略打"狂信徒 + 颚虫"，53 HP 打到只剩 15（这还算上了燃血徽记战后回的 6 点）。
2. **精英强度差距太大。** 哨兵几乎是白送遗物，地精贵族则有一半概率杀死 bot。
3. **Boss 偏向毒流。** 黑曜守望者每 4 回合叠 +4 金属化、+12 格挡和 +3 力量，纯攻击流越打越吃亏，而毒无视格挡。赤铁卫士即使打到 Boss，也只有约 12% 能赢。
4. **赤铁卫士整体偏弱。**
   - 职业过牌只有剑柄突刺、耸肩卸力、血祭契约，战斗专注还是坏的（见下一节）。
   - 力量来源只有炽焰战意和恶魔化身两张牌。

| 2 | **玩家的易伤/虚弱/脆弱在玩家回合开始时就减 1** | `engine.ts:1388-1391` | 敌人给的 1 层减益永远不生效（骸骨护卫的易伤 1，石像鬼的虚弱 1 / 脆弱 1），2 层的只生效 1 回合 | 改到敌人回合结束时递减，并对本回合刚施加的层数跳过一次 |

| 5 | **干净 clone 后 `npm install` 失败。** esbuild ^0.25 和 vite 8 要求的 ^0.27/^0.28 冲突，仓库里也没有 lockfile | `package.json` | 照 README 的步骤跑不起来（我是用 `--legacy-peer-deps` 才装上的） | 把 esbuild 升到 ^0.28，或者直接删掉（tsx 自带一份），再提交 `package-lock.json` |
| 6 | **英文模式下，战斗日志和飘字仍然是中文**（如"格挡""力量 +2""进入第 15 层战斗"），因为这些字符串写死在引擎里 | `engine.ts` 各处的 `text:` 和 `log.push` | 和 README 的"全部即时切换"不符 | 引擎只产出结构化事件（如 `{kind:'block', amount}`），由 UI 层翻译 |

| 8 | **营火"歇息疗伤"总是显示 +24 HP**，即使只缺 5 HP | `RoomViews` 营火 | 小误导 | 显示 `min(30% 最大生命, 缺失生命)` |
| 9 | **几处死内容** | `cards.ts:770`、`potions.ts` | 这些系统写了但没起作用 | 见下面三项 |

第 9 项的三处死内容和修法：
- 诅咒「蚀骨痛楚」整局都拿不到 → 接到事件的代价里。
- 「血精药水」标为稀有，但掉率和其他药水一样 → 药水按稀有度加权掉落。
- 进阶 0–2 开局就全部解锁 → 改为逐级解锁。

## 五、UI/UX 问题

1. **手牌会换行。**
   - **现状**：手牌容器用的是 `flex-wrap`（`CombatArenaView.tsx` 约 1127 行）。1440×900 和 1920×1080 下都只排 4 张一行，第 5 张掉到首屏以下，要滚动才能看到；灵蛇戒环开局抽 7 张时更糟。
   - **建议**：改成单行、扇形、可重叠的手牌，卡宽用 `clamp()` 随视口缩放。
2. **顶栏会挤掉核心按钮。**
   - **现状**：拿到 4 件遗物后顶栏变成两行。1440×900 下，"结束回合"和能量球被推到屏幕边缘，只露出一半。
   - **建议**：遗物改成一排小图标加悬停提示，顶栏固定为一行高。
3. **手机上没法玩。**
   - **现状**：在 375 宽的手机模拟下，"结束回合"按钮在页面约两屏以下。
   - **建议**：要么声明只支持桌面，要么做竖屏布局（敌人在上，手牌固定在底部）。
4. **卡牌辨识度低。**
   - **现状**：52 张牌共用 6 张插图，奖励界面经常是三张一模一样的红色斩击。
   - **建议**：短期按卡牌配不同的图标/符号和框色，缩小插图区、放大文字；长期给每张牌一张图。
5. **敌人行动一次性结算。**
   - **现状**：所有敌人在 420ms 内同时行动完，多个敌人时看不清谁打了多少。
   - **建议**：按敌人逐个播放，每个 300–400ms。
6. **空格直接结束回合，没有防误触。**
   - **建议**：如果还有能量和可出的牌，第一次按空格时先给提示。
7. **地图看不全，分叉也少。**
   - **现状**：一屏只能看到半张地图。试玩时第 1 层中间的节点只有一条路可走。
   - **建议**：地图默认滚到当前层，把 Boss 固定显示在顶部，并提高分叉概率。
8. **资源体积太大。**
   - **现状**：图片共 20 MB，都是 JPG，单张约 1 MB。
   - **建议**：转成 WebP 或 AVIF，每张压到约 100–200 KB，首屏加载能快 5–10 倍。
9. **每次刷新都重播开场动画。**
   - **建议**：只在第一次进入时播放。

## 六、内容与原创性（最关键）

### 6.1 现状

英文名、数值、敌人设计都和《杀戮尖塔》一致：

- **卡牌**：Bash（8 伤 + 2 易伤）、Pommel Strike（9 伤抽 1，升级后 10 伤抽 2）、Demon Form、Corpse Explosion、Catalyst、Phantasmal Killer、Apotheosis……
- **遗物**：Burning Blood、Ring of the Snake、Vajra、Anchor、Kunai、Shuriken、Mercury Hourglass……
- **敌人**：
  - 设计照搬：Cultist（仪式 3）、Jaw Worm（11 伤撕咬）、Gremlin Nob（技能激怒）、Lagavulin（睡眠 + 金属化）、Sentry（塞伤口）。
  - 代码 id 和图片文件名也是原名，例如 `gremlin_nob`、`lagavulin`。
- **起始牌组**：结构和 Ironclad、Silent 一样。

问题有两层：

- **版权风险。** 公开仓库直接用另一款商业游戏的卡名、遗物名和敌人设计，有知识产权风险。作品集的读者也会一眼认出是换皮。
- **没有自己的钩子。** 熟悉原作的玩家已经知道最优解；不熟悉的玩家会觉得这是个"小号杀戮尖塔"。

### 6.2 建议：围绕"烬"做一个标志机制

**原则**：保留"意图 + 能量 + 构筑 + 爬塔"这套品类骨架，这是公共玩法。**所有具体的卡牌、遗物、敌人都重新设计和命名**，再加一个只属于本作的核心系统。

**推荐方向：余烬（Embers）系统**

- **怎么获得**：
  - 每消耗一张牌，获得 1 点余烬。
  - 玩家每回合可以把 1 张手牌"焚烧"掉代替弃牌，同样获得 1 点余烬。
  - 余烬在本场战斗内累积。
- **两个职业用法不同**：
  - 赤铁卫士「淬火」：花 X 点余烬，让下一张攻击牌伤害 +2X，或者立即获得 3X 格挡。这给他补上了第二条成长线，也正好用来对付 Boss 的高格挡。
  - 暗影织者「灰雾」：花 X 点余烬，给所有敌人 X 层中毒，或者抽 X/2 张牌。
- **营火新增「献烬」**：永久焚毁牌组里的 1 张牌，换 +5 最大生命，或者下一场战斗开局带 3 点余烬。删牌和成长绑在一起，营火的选择更有分量。
- **和 Boss 联动**：黑曜守望者的「灭世炼狱射线」改成先蓄力一回合。蓄力期间，玩家单回合造成 ≥X 伤害就能打断它，余烬爆发正是打断手段。

这个系统和"烬塔"的主题一致，能同时修好"赤铁卫士缺爆发"和"Boss 偏毒流"两个平衡问题，也给消耗、弃牌找到了现在缺少的收益。上线前先用模拟器跑一遍数值。

**备选方向**（如果余烬不合心意）：

- **「塔在燃烧」**：每层有热度，战斗回合越多热度越高，热度影响奖励和下一场敌人的强度。强调节奏。
- **「灰烬记忆」**：本局被消耗的牌，下一层会以 0 费的弱化"灰烬版"回到牌组，形成跨战斗的消耗构筑。

### 6.3 内容量目标（第一个"可玩版本"）

| 项目 | 现在 | 目标 |
|---|---|---|
| 每职业可得卡牌 | 赤铁卫士 19 张、暗影织者 17 张，另有 4 张中立 | 每职业 35 张，中立 8 张 |
| 遗物 | 12 件可得，没有 Boss 遗物 | 25 件，其中 4–5 件是有代价的 Boss 遗物 |
| 事件 | 4 个，基本没有坏选项 | 10 个以上，每个都有真实取舍（把诅咒接进来） |
| 普通怪 / 精英 / Boss | 5 / 3 / 1 | 9 / 4 / 2（Boss 随机其一），或者再加一幕 |
| 进阶 | 3 级，开局全部解锁 | 10 级，逐级解锁，每级加一条规则 |

## 七、平衡改进（具体数值建议）

1. **削平第 5 层断崖。**
   - 1–4 层：还是单体怪，但第 3–4 层加入"强单体"，例如 HP 55–60 的骸骨护卫。
   - 5–7 层：只刷弱双怪，例如两只小史莱姆，或掠夺者 + 小史莱姆。
   - 8–14 层：才进入现在的双怪池，并且敌人 HP 每层 +3%。
   - 地图第 2–4 层允许出现 1 个营火或商人。
2. **狂信徒 + 颚虫。**
   - 狂信徒：在这个组合里 HP 降到 40–44，或者仪式从 3 改成 2。
   - 颚虫：在这个组合里第 1 回合先防御，不要开局就打 11 伤。
3. **精英。**
   - 地精贵族：怒吼之后才激怒，HP 从 86 降到 80。
   - 哨兵：HP 从 42/44 提到 50/52，激光从 9 提到 11，伤口改为洗进抽牌堆。
   - 目标：三种精英的 bot 战败率都落在 15–35%。
4. **Boss。**
   - 金属化每轮从 +4 改为 +2，上限 8。
   - 把"灭世射线"改成可打断的蓄力（见 6.2）。
   - 目标：两个职业到达 Boss 后的 bot 胜率都在 25–45%，彼此相差不到 1.5 倍。
5. **赤铁卫士。** 修好战斗专注；新增 2 张过牌牌，再加 1 张不是能力牌的力量来源（例如"本回合 +2 力量"）。
6. **卡牌奖励稀有度。**
   - 稀有卡出现率：普通战从 12% 降到约 5%（带保底递增），精英战从 28% 降到约 15%。
   - 预升级概率：从 10% / 25% 降到 5% / 12%。
   - 原因：卡池这么小，高稀有率会让每局拿到的牌都差不多。
7. **事件。**
   - 低语泉眼「痛饮」：回复 22 HP 再送一张稀有卡，没有任何代价，严格占优。改成加一张诅咒，或者改成两张随机稀有卡二选一。
   - 「投币」：25 金换 50% 概率得遗物，期望收益太高，提到 60 金。
8. **第 8 层宝箱不该开出稀有遗物。** 烬火核心（+1 能量）在这里出现会直接决定一局，宝箱只出普通或罕见遗物。

**把模拟器当回归测试用。** 每次改完数值后运行 `npx tsx scripts/balance_sim.ts`，至少盯住三个数：

- 5–7 层的死亡占比
- 各精英的战败率
- 两个职业的胜率比

## 八、工程建议

1. **依赖。**
   - 修好 esbuild 冲突，提交 lockfile。
   - 删掉没用到的 `@google/genai`、`express`、`dotenv`。
   - `package.json` 的 `name` 从 `react-example` 改成正式名字。
   - `metadata.json` 里的 Gemini 能力声明可以删掉。
2. **效果系统。**
   - **现状**：`CardDef` 有 40 多个可选字段，`playCard` 一个函数近 400 行，遗物判断散落成 `hasRelic(…,'xxx')`。每加一个新机制都会更难改。
   - **建议**：卡牌效果改成效果列表，例如 `effects: [{type:'damage', amount:6}, {type:'applyStatus', status:'vulnerable', amount:2}]`。遗物改用钩子：`onCombatStart`、`onTurnStart`、`onCardPlayed`、`onAttack`。
3. **随机数。**
   - **现状**：全部用 `Math.random`。
   - **建议**：换成带种子的 RNG（例如 mulberry32），种子存在 `RunState` 里。这样能复现 bug、做每日挑战，模拟结果也能重复。
4. **房间逻辑。**
   - **现状**：营火、商店、奖励、宝箱的处理都写在 `App.tsx` 里，测试和模拟都调用不到，模拟器只能自己重写一份。
   - **建议**：挪进 `engine.ts`。
5. **文案。** 引擎里不要出现中文，只产出结构化事件和 i18n key。
6. **CI。** 把 `verify_game.ts` 和 `balance_sim.ts`（小样本，只检查数值区间）挂到 `npm test` 和 GitHub Actions。

## 九、路线图

| 阶段 | 时间 | 内容 | 完成标准 |
|---|---|---|---|
| P0 修复 | 1–2 天 | 第四节的 Bug 1–6；手牌改成单行；遗物不再挤占顶栏；依赖能正常安装 | 干净 clone 后能直接 `npm install && npm run dev`；1440×900 下不用滚动 |
| P1 平衡 | 约 1 周 | 第七节第 1–8 条；模拟器接入 CI | 5–7 层死亡占比 <25%；精英战败率在 15–35%；职业胜率比 <1.5 倍 |
| P2 原创化 | 2–4 周 | 所有卡牌、遗物、敌人重新设计和命名；做出余烬系统；内容量补到 6.3 的目标 | 不再出现《杀戮尖塔》的名称和数值组合；每职业 ≥35 张牌 |
| P3 打磨 | 持续 | 敌人逐个行动的动画、手机布局、WebP 资源、每日种子挑战、进阶 10 级 | 手机上能完整打完一局；首屏资源 <3 MB |

**建议顺序：先做 P0，再出 P2 的设计稿，最后做 P1。** 原创化会改掉大部分数值，在旧卡池上细调平衡很可能白做。先定下余烬机制和新卡池，再用模拟器调数值。
